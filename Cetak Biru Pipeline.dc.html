CETAK BIRU PIPELINE

Bikin situsnya jalan otomatis

Panduan arsitektur untuk developer: gimana front-end yang sudah jadi ini disambungkan ke worker terjadwal supaya konten (kode redeem, event, tier, berita) terisi & terupdate otomatis tanpa disentuh manual.

1 · Model mental

Situs = pembaca cache, bukan penarik data. Yang bikin "otomatis" adalah worker terjadwal di sisi server yang rutin menarik sumber, merapikan, lalu menaruh hasilnya sebagai JSON/DB yang dibaca situs. Front-end tidak pernah memanggil API pihak ketiga langsung (hindari rate-limit, CORS, & kunci API bocor).

01 · TARIK
Worker panggil tiap sumber sesuai jadwalnya.
02 · NORMALISASI
Gabung ke satu skema konsisten + tag game/genre/bahasa.
03 · CACHE
Simpan JSON/DB + aset (icon/gambar) di server sendiri.
04 · TAYANG
Build ulang halaman statis; situs baca cache.

Beda konten beda frekuensi. Yang cepat basi ditarik sering; metadata yang jarang berubah cukup harian.

3 · Peta sumber → fitur

Detail endpoint, lisensi, & atribusi ada di dokumen "Riset Sumber Data". Ringkasnya: API gratis (hoyo-codes, GamerPower, FreeToGame, Data Dragon), API perlu key (RAWG, PandaScore), dan sumber referensi (Prydwen/Game8 — kurasi, jangan salin mentah).

4 · Saran tech stack

Worker / scheduler

Serverless cron (Cloudflare Workers Cron, Vercel Cron, atau GitHub Actions terjadwal) menjalankan skrip Node/TS penarik. Idempoten & retry-safe.

Penyimpanan

JSON statis di object storage/CDN (mis. R2/S3) untuk yang read-heavy; database (Postgres/SQLite/KV) untuk arsip kode & query. Kode expired diarsipkan, bukan dihapus.

Aset

Icon & gambar di-mirror ke server/CDN sendiri saat ditarik — jangan hotlink permanen ke Fandom/CDN pihak ketiga (bisa mati/berubah).

Front-end

Halaman statis (SSG) yang di-rebuild saat cache berubah — cepat & ramah SEO. Countdown tetap dihitung real-time di klien dari data-deadline.

Halaman game auto-generate

Saat worker mendeteksi game baru (online/live-service), generate halaman dari template Game Genshin.dc.html + daftarkan ke navigasi, sitemap, & mapping cross-link.

5 · Filter cakupan & skala

Worker hanya proses game online / live-service — yang punya event berkala & kode redeem. Game offline/single-player di-skip (tak cocok model auto-update). Saat game makin banyak: search jadi pintu utama, filter + pagination jaga halaman ringan, tiap game punya halaman + arsip sendiri.

6 · Bilingual & SEO

Toggle ID/EN di klien buat kenyamanan, tapi SEO butuh halaman per-bahasa: generate URL terpisah (/id/… & /en/…) yang di-render statis, plus tag hreflang antar versi. Konten disimpan dua bahasa di cache (ID resmi jika ada; kalau tidak, terjemahkan — kecuali jargon teknis yang dibiarkan asli). Sertakan sitemap.xml per bahasa.

7 · Fidelitas & legal

Data faktual (skill, stat, reward, nama/durasi event) diambil verbatim dari sumber — jangan diparafrase; jargon tanpa terjemahan resmi dibiarkan bahasa aslinya. Verifikasi status kode sebelum tayang. Patuhi atribusi tiap lisensi (RAWG, GamerPower, FreeToGame), tampilkan disclaimer "not endorsed by Riot Games", hormati robots.txt & rate limit, dan jaga situs bersih dari judol.

8 · Urutan bangun

  1. Kode redeem — hoyo-codes + GamerPower (API gratis, paling dicari). Sambungkan cache → halaman Kode.
  2. Katalog game — RAWG + FreeToGame → Jelajah Game + kartu.
  3. Berita — RSS aggregator → halaman Berita + Artikel.
  4. Event & countdown — HoYoLAB/Paimon → halaman Event + per-game.
  5. Tier & data karakter — StarRailRes/Enka/Data Dragon → Tier List + modal.
  6. Auto-generate halaman game + sitemap + i18n per-bahasa.

Front-end (semua halaman .dc.html) sudah siap sebagai "cangkang" dengan slot data yang jelas. Yang tersisa adalah membangun worker + cache dan menyambungkannya sesuai dokumen ini. Referensi endpoint & lisensi: "Riset Sumber Data".
